# MajDHTProber

MajDHTProber 是 [MajDHTNetwork](modules/MajDHTNetwork)（MajDHT v1 协议）的图形化探测与调试工具，基于 **.NET 10** 与 **Avalonia 12**。它在本进程内托管一个或多个 `MajDHTNode`，用来查看网络中的节点、手动接入节点、检查连接状态，并提供文件拉取、节点间通信测试等调试功能。

## 功能

| 页面 | 内容 |
| --- | --- |
| 概览 | 当前节点的 ID、能力、可达性、外部地址、NAT 映射、通告端点与健康指标；启动 / 停止 / 引导 / 刷新邻居；创建本地测试网络（多个回环节点）。 |
| 节点 | 网络内所有已知节点（路由表、查找结果、提供者、中继提示、手动添加、本地节点），按状态筛选与搜索；手动按端点添加节点；节点详情：连接状态、通告端点、中继提示、身份工作量、租期、传输统计；端点探测、路由探测、注册中继、经中继打洞。 |
| 内容 | 发布文本 / 文件、发布别名、重新公告、撤回、停止提供；按键或记录码拉取文件（内存预览或保存到文件，带进度与完整校验）；解析键、查找提供者；导入他人内容的本地副本。 |
| 调试工具 | 端点探测（类 ping：签名 Hello + 加密 Ping，统计丢失率、往返时间与对方观察到的本机地址）、路由查找（XOR 距离）、单块读取（指定提供者与中继，十六进制预览）、中继注册与 TCP / UDP 打洞、端到端通信测试、按节点与路由的传输统计。 |
| 日志 | 协议库与探测器的实时日志，按级别 / 来源 / 关键字筛选，暂停、跟随、导出。 |
| 设置 | 监听与通告地址、端口、优先传输、能力、引导端点、身份工作量、超时等协议参数；身份持久化与重置；路由表持久化；主题与日志级别。 |

### 连接状态

| 状态 | 含义 |
| --- | --- |
| 已连接 | 节点是当前节点路由表中的有效条目，可作为查找跳点。 |
| 可达 | 最近 5 分钟内有经过认证的交互或探测成功，但不在路由表中（如私有节点、未验证端点）。 |
| 已发现 | 仅从查找结果或引用得知，尚未直接交互。 |
| 已断开 | 上次成功之后发生过请求失败或探测失败。 |
| 已过期 | 节点签名联系人的租期已过期。 |

## 实现要点

探测器只使用 MajDHTNetwork 的公开 API 与扩展点，不修改子模块：

- **节点追踪**：每个托管节点使用 `TrackingRoutingTable`（包装库自带的 `KademliaDHTRoutingTable` 的 `IDHTRoutingTable`），只观察、不干预：记录节点观察到的每个经过认证的联系人与因失败而移除的节点，汇总到 `PeerDirectory`。联系人是否进入路由表完全由库决定。
- **端点探测**：直接使用库公开的协议层（`SocketTransport`、`Packet`、`HelloMessage` 等编解码器）。每次探测以独立的“探针身份”绑定一个只发不收的传输：先发送签名 Hello 得到端点上节点的签名联系人、往返时间和对方观察到的本机地址，再向同一端点发送一次加密 Ping，分别计时；不回退到另一种传输。探针不通告端点、不应答任何请求，不会进入对方路由表；探测器也会把探针身份从自己托管节点的节点列表中过滤掉。
- **手动添加节点**：调用库的 `MajDHTNode.AddPeerAsync`：当前节点自己向端点发送签名 Hello（先用所选传输，无应答时在同一端口改用另一种），把应答节点作为已验证联系人加入路由表，若其具备中继能力且已启用 NAT 穿透则注册为中继，随后经它查找邻居，与引导端点的处理完全一致。
- **本地测试网络**：额外节点监听 `127.0.0.1` 的系统分配端口，经已运行的节点引导，并通过同样的 `AddPeerAsync` 在回环上与每个已运行节点双向互联，便于在无外部网络时测试节点间通信。
- **路由表持久化**：主节点停止时用 `ExportRoutingTable` 把路由表中节点的 ID 与端点保存到用户数据目录，下次启动后在后台用 `RestoreRoutingTableAsync` 重新联系这些节点，只接纳仍以原身份应答的节点；快照不含密钥、签名或内容。本地测试网络的节点端口每次不同，不保存路由表。
- **身份**：节点身份需要满足网络的身份工作量（默认 12 位，生成可能需要数秒到数十秒），因此身份按名称缓存，可选保存到用户数据目录，节点 ID 在重启后保持不变。种子从不写入日志。

| 路径 | 内容 |
| --- | --- |

## 构建与运行

需要 .NET 10 SDK，并先拉取子模块：

```powershell
git submodule update --init
dotnet build MajDHTProber.slnx -c Release
dotnet run --project src/MajDHTProber/MajDHTProber.csproj -c Release
```

运行测试：

```powershell
dotnet test src/MajDHTProber.Tests/MajDHTProber.Tests.csproj -c Release
```

## 数据与配置

设置（`settings.json`）、身份种子（`identities/*.seed`）与主节点的路由表快照（`routing/*.routing`）保存在 `%APPDATA%\MajDHTProber`（Linux / macOS 为对应的应用数据目录）。设置环境变量 `MAJDHTPROBER_HOME` 可改用其他目录，例如便携运行或隔离测试。

默认主节点监听 `0.0.0.0` 的 TCP / UDP `42000` 端口、身份工作量 12 位。监听通配地址且未填写通告地址时，节点不会通告任何端点：它可以主动探测、查找和下载，但其他节点无法主动连接它；需要被发现时，请在设置中监听具体地址或填写通告地址（设置页会列出本机网卡地址供选择）。身份工作量必须与被探测网络一致。

## 已知限制

- 打洞、可达性检查与中继依赖真实 NAT 环境，仓库中的测试只覆盖回环网络。
- 恢复路由表时，每个不再应答的已保存节点都要等待请求超时，一次最多同时联系 16 个。
- 本地测试网络的节点使用回环地址，只能与本机节点互通。
